# 🏙️ Контрольные вопросы

### 📌1. Как записать линейную модель в векторной форме и зачем добавляют признак, всегда равный единице?

Линейная модель в векторной форме записывается как:

**ŷ = Xw** | **y = Xa**

где:
- X — матрица признаков;
- w — вектор коэффициентов модели;
- ŷ — вектор предсказанных значений.

Столбец единиц добавляется для учёта свободного коэффициента w₀ (intercept). Благодаря этому модель учитывает постоянное смещение и все коэффициенты можно вычислить одним матричным выражением.

### 📌2. Выведите формулу w = (XᵀX)⁻¹Xᵀy из условия минимума MSE. Почему этот минимум единственный?

Функция среднеквадратичной ошибки: **MSE(w) = (1/n) · (Xw − y)ᵀ(Xw − y)**

Находим производную по w: **∇MSE(w) = (2/n) · Xᵀ(Xw − y)**

Приравниваем её к нулю: **Xᵀ(Xw − y) = 0**

Раскрываем скобки: **XᵀXw = Xᵀy**

Отсюда получаем: **w = (XᵀX)⁻¹Xᵀy**


### 📌3. В каких случаях матрица XᵀX вырождена? Приведите пример из этой работы.

Матрица XᵀX становится вырожденной, когда признаки линейно зависимы. Например, один столбец является копией другого.

В П2 нашего проекта мы продублировали признак G2.

Полученные результаты:

| Метод | Результат |
|---|---|
| np.linalg.inv | Singular matrix |
| np.linalg.solve | Singular matrix |
| np.linalg.lstsq | Решение найдено |
| LinearRegression | Решение найдено |

Ранг матрицы составил 2 при наличии 3 столбцов.
Таким образом, дублирование G2 сделало матрицу XᵀX вырожденной, поскольку она потеряла полный столбцовый ранг.

### 📌4. Почему вместо явного обращения матрицы используют np.linalg.solve?

Метод `np.linalg.solve()` решает систему линейных уравнений напрямую, без явного вычисления обратной матрицы.

Его преимущества:
- лучшая численная устойчивость;
- меньше лишних вычислений;
- обычно более высокая эффективность.

Поэтому вместо выражения: `np.linalg.inv(X.T @ X) @ X.T @ y`

предпочтительнее использовать: `np.linalg.solve(X.T @ X, X.T @ y)`

При вырожденной матрице оба метода могут завершиться ошибкой. В таких случаях применяют `np.linalg.lstsq()`.

### 📌5. Как с помощью бинаризации учесть нелинейную зависимость в линейной модели?

Бинаризация позволяет разделить числовой признак на интервалы и представить каждый интервал отдельным индикатором.

В нашем проекте использован `KBinsDiscretizer` для признака `absences` — количества пропущенных занятий.

Проверены:
- n_bins = 4, 8, 12, 20;
- strategy = uniform и quantile.

Лучший результат получен при `n_bins=20` и `strategy="quantile"`:

**CV R² = 0.824525**

Базовая модель имела CV R² = 0.821636.

Таким образом, бинаризация позволила модели учитывать различное влияние количества пропусков в отдельных диапазонах, сохраняя линейность по преобразованным признакам.

### 📌6. Какой симптом переобучения характерен для линейных моделей? Покажите его на результатах шага 7.

Основные симптомы переобучения линейной модели:
- значительное снижение ошибки на обучающей выборке;
- высокая ошибка на новых данных;
- чрезмерно большие коэффициенты модели.

В шаге 7 методички сравнивались полиномы разных степеней на небольшой выборке.

| Степень полинома | Train RMSE | Test RMSE |
|---|---:|---:|
| 1 | 749 | 766 |
| 4 | 588 | 789 |
| 15 | 522 | 186 205 |

При увеличении степени до 15 ошибка на обучении снизилась до 522, но ошибка на тесте выросла до 186 205.

После добавления Ridge-регуляризации с α = 100 тестовая ошибка уменьшилась до 772.

Таким образом, регуляризация ограничивает коэффициенты и помогает уменьшить переобучение.

### 📌. Чем отличаются Ridge и Lasso? Почему Lasso обнулил по одному столбцу в каждой группе one-hot?

Ridge использует L2-регуляризацию, то есть штраф за сумму квадратов коэффициентов.

**Ridge: MSE + α · Σwⱼ²**

Lasso использует L1-регуляризацию — штраф за сумму модулей коэффициентов.

**Lasso: MSE + α · Σ|wⱼ|**

Главное отличие:
- Ridge уменьшает величину коэффициентов, обычно не обнуляя их.
- Lasso может обнулять коэффициенты, выполняя отбор признаков.

При OneHotEncoder без `drop="first"` для каждой категории создаётся отдельный столбец. Сумма индикаторов одной категориальной переменной равна единице, поэтому при наличии intercept возникает линейная зависимость.

Lasso может обнулить один или несколько таких столбцов, оставив остальные. Однако обнуление ровно одного столбца в каждой группе не гарантируется.

В нашем проекте Lasso обнулила 53 из 65 коэффициентов. После использования `OneHotEncoder(drop="first")` количество коэффициентов уменьшилось до 48, из которых 31 стал нулевым.

Это объясняется изменением кодирования признаков и действием L1-регуляризации.

### 📌8. Почему перед регуляризацией признаки нужно стандартизовать и по какой выборке считать μ и σ?

Регуляризация штрафует модель за величину коэффициентов. Если признаки имеют разные масштабы, штраф будет действовать на них неравномерно.

Стандартизация выполняется по формуле:

**z = (x − μ) / σ**

где:
- μ — среднее значение признака;
- σ — стандартное отклонение.

Среднее и стандартное отклонение необходимо рассчитывать только на обучающей выборке.

В нашем проекте используется `StandardScaler` внутри Pipeline.

Это предотвращает утечку информации из тестовой выборки и обеспечивает корректную кросс-валидацию.

### 📌9. Почему вес rooms заметный, а падение R² при его удалении почти нулевое?

В примере методички число комнат (`rooms`)  связано с площадью квартиры (`area`).

Поэтому коэффициент rooms может быть заметным, однако его удаление почти не влияет на R²: информация о размере квартиры уже содержится в признаке area.

Аналогичная ситуация наблюдается в нашем проекте.

Признак G1 имеет коэффициент около 0.4762, однако его удаление снижает CV R² всего на 0.005589.

Причина — высокая корреляция между G1 и G2

Таким образом, большой коэффициент не всегда означает высокую уникальную важность признака. При наличии коррелирующих переменных модель может использовать информацию из других столбцов.

### 📌10. Какие файлы проекта хранятся в Git, а какие нет? Почему модель не коммитят?

В Git хранятся:
- `src/prepare.py` — подготовка данных;
- `src/train.py` — обучение модели;
- `params.json` — параметры эксперимента;
- `metrics.json` — результаты обучения;
- `requirements.txt` — зависимости;
- `README.md` — описание проекта;
- `docs/lab8.md` — отчёт;

Не хранятся:
- `.venv/` — виртуальное окружение;

- `.ipynb_checkpoints/` — контрольные копии Jupyter;
- `models/*.joblib` — сохранённые обученные модели.

Модель не коммитят, потому что она является бинарным артефактом, который можно воспроизвести с помощью исходных данных, кода и параметров. Хранение таких файлов увеличивает размер репозитория.

### 📌11. Зачем эксперименты проводят в отдельных ветках и как сравнить их результаты средствами Git?

Отдельные ветки позволяют независимо изменять параметры модели, сохранять результаты и не нарушать стабильную версию проекта в main.

В нашем проекте созданы ветки:
- `exp/bins` — бинаризация признака absences;
- `exp/ridge` — Ridge-регуляризация;
- `exp/lasso` — Lasso-регуляризация;
- `exp/interpretation` — интерпретация модели.

Метрики разных экспериментов сравниваются командами:

`git diff main exp/bins -- metrics.json`
`git diff main exp/ridge -- metrics.json`
`git diff main exp/lasso -- metrics.json`
Команда `git log --oneline --graph --decorate` позволяет просмотреть историю экспериментов.

Лучшие изменения объединяются с основной веткой через `git merge`, а итоговая версия фиксируется тегом `v0.3`.

### 📌12. Почему эксперимент выбирают по cv_r2, а не по метрикам на тестовой выборке?

Тестовая выборка должна использоваться только для итоговой независимой оценки модели.

Если многократно сравнивать эксперименты по тестовым метрикам и выбирать лучший, модель косвенно подстраивается под тестовую выборку. Это приводит к завышенной оценке качества.

Поэтому подбор признаков, гиперпараметров и методов регуляризации выполняется на обучающей выборке с использованием кросс-валидации.

В нашем проекте основным показателем выбора является CV R², а дополнительным — CV RMSE.

Наилучший результат показала модель Lasso:

- CV R² = 0.8378;
- CV RMSE = 1.2995.

После выбора модели тестовая выборка используется для итоговой оценки её качества на ранее не использовавшихся наблюдениях.
