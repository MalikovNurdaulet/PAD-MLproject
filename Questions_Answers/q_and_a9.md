
# 🏙️ Контрольные вопросы — ЛР9

### 📌1. Чем задача классификации отличается от регрессии? Что такое положительный класс?

**Регрессия** предсказывает числовое значение
**классификация** определяет принадлежность объекта к определённому классу.

В проекте:
- **Регрессия (ЛР8)** — прогнозирование итоговой оценки `G3` по шкале от 0 до 20.
- **Классификация (ЛР9)** — определение риска академической неуспеваемости.

Положительный класс — это класс, обозначенный как `1`, то есть событие, которое необходимо обнаружить.

В проекте:
- `at_risk = 1` — учащийся находится в группе риска (`G3 < 10`).
- `at_risk = 0` — учащийся не находится в группе риска (`G3 >= 10`).

Задача классификатора — определить вероятность принадлежности учащегося к группе риска.

### 📌2. Как логистическая регрессия получает вероятность из линейной модели? Чему равно z, если вероятность равна 0,5?

Логистическая регрессия вычисляет линейную комбинацию признаков: **z = w₀ + w₁x₁ + w₂x₂ + ... + wₙxₙ**

Затем применяет сигмоидную функцию: **P(y = 1 | x) = 1 / (1 + e⁻ᶻ)**

Сигмоида преобразует любое значение z в вероятность от 0 до 1.

Если вероятность равна 0,5: **0,5 = 1 / (1 + e⁻ᶻ)**

Отсюда: **z = 0**

При стандартном пороге 0,5 модель относит объект к положительному классу, если вероятность не меньше 0,5.

В проекте после подбора порога используется значение **0,22**, чтобы выявлять больше учащихся группы риска.

### 📌4. Запишите формулы precision, recall и F1. Посчитайте их по матрице ошибок шага 5.

В проекте для базовой LogisticRegression получена матрица:

| Факт / Прогноз | Нет риска (0) | Есть риск (1) |

### 📌5. Что в кейсе этой работы означают FP и FN? Какая ошибка дороже для сервиса?

В примере методички рассматривается прогнозирование быстрой сдачи квартир.

- **FP** — модель прогнозирует, что квартира сдастся за 14 дней, но этого не происходит.
- **FN** — модель прогнозирует, что квартира не сдастся за 14 дней, хотя она сдаётся.

Для сервиса FP может привести к неверным рекомендациям арендодателям
FN — к пропуску перспективных предложений. Какая ошибка дороже, зависит от целей сервиса.

В проекте академических рисков:
- **FP** — учащийся ошибочно отнесён к группе риска.
- **FN** — учащийся действительно находится в группе риска, но модель этого не обнаружила.

**Для образовательной организации FN считается более критичной ошибкой**, поскольку учащийся может не получить своевременную академическую поддержку.

Поэтому в проекте при выборе порога особое внимание уделяется повышению Recall.

### 📌6. Как изменяются precision и recall при повышении порога? Почему?

Порог классификации определяет, при какой вероятности модель относит объект к положительному классу.

При повышении порога модель реже предсказывает класс 1:

- Precision обычно увеличивается.
- Recall уменьшается.
- Количество положительных прогнозов сокращается.

При снижении порога модель чаще предсказывает класс 1:

- Recall увеличивается.
- Precision может уменьшаться.
- Количество ложных тревог обычно растёт.

В проекте:
| Порог | Precision | Recall |
|---|---:|---:|
| 0,50 | 0,7727 | 0,6800 |
| 0,22 | 0,6875 | 0,8800 |

Значения рассчитаны на кросс-валидационных прогнозах обучающей выборки.

**Вывод:** снижение порога до 0,22 увеличило полноту выявления учащихся группы риска с 68% до 88%, но привело к снижению Precision.

Такой выбор оправдан, поскольку пропуск реального академического риска считается более дорогой ошибкой.

### 📌7. Что показывает ROC-AUC и почему эта метрика не зависит от порога?

**ROC-AUC** показывает способность модели различать положительный и отрицательный классы при разных порогах классификации.

ROC-кривая строится по двум показателям:

**TPR = TP / (TP + FN)**

**FPR = FP / (FP + TN)**

ROC-AUC — площадь под ROC-кривой.

Интерпретация:

- ROC-AUC = 0,5 — качество случайного угадывания.
- ROC-AUC = 1,0 — идеальное разделение классов.

ROC-AUC не зависит от одного выбранного порога, поскольку оценивает ранжирование объектов по вероятностям на всех возможных порогах.

В нашем проекте базовая LogisticRegression получила: **CV ROC-AUC = 0,9663**

При изменении порога с 0,50 до 0,22 ROC-AUC не изменился, поскольку сами вероятности модели остались прежними.

### 📌8. Зачем при разбиении данных указывают stratify?

Параметр `stratify=y` позволяет сохранить приблизительно одинаковое распределение классов в обучающей и тестовой выборках.

Это особенно важно при несбалансированных данных.

В датасете:
- Класс 0 — 549 учащихся.
- Класс 1 — 100 учащихся.

Использовано разбиение: `train_test_split(X, y, test_size=0.25, random_state=42, stratify=y)`

Результат:
| Выборка | Класс 0 | Класс 1 |
|---|---:|---:|
| Train | 411 | 75 |
| Test | 138 | 25 |

Стратификация помогает избежать ситуации, когда редкий класс непропорционально представлен в одной из выборок.

### 📌11. Почему порог хранится в params.json, а эксперимент выбирают по cv_f1, а не по тестовым метрикам?

Порог классификации является параметром модели, поскольку напрямую влияет на её предсказания.

Cохранение в JSON обеспечивает:
- воспроизводимость эксперимента;
- возможность изменять порог без переписывания кода;
- сравнение разных версий модели через Git.

В  проекте порог хранится в `params_clf.json`: `"threshold": 0.22`

Метрики сохраняются в `metrics_clf.json`.

Эксперименты выбираются по **CV F1**, поскольку кросс-валидация позволяет оценить качество на обучающей выборке без использования тестовых данных для подбора.


В проекте сравнивались:
| Эксперимент | CV F1 |
|---|---:|
| Базовая LogisticRegression | 0,7220 |
| Порог 0,22 | **0,7712** |
| class_weight="balanced" | 0,7476 |
| DecisionTreeClassifier | 0,7250 |

Наилучший результат показала LogisticRegression с порогом 0,22.
